# EARS

Templates for phrasing requirements so that they read unambiguously (Mavin et al., Rolls-Royce).

## How to apply (project suggestion)

1. Choose a template by type: always, event-driven, state-driven, unwanted case, optional.
2. Write: “When <event>, the system shall <action>.”
3. Check that the requirement is single, measurable and without “and/or”.
